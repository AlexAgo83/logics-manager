# Changelog

What changed in each release of `@grifhinz/logics-manager`. Every entry links its full
note, which carries the reasoning and any migration detail this summary leaves out.

Releases before 2.15.0 are on [GitHub Releases](https://github.com/AlexAgo83/logics-manager/releases) only.

Generated by `npm run build:changelog` from `changelogs/`. Do not edit by hand.

## 2.22.0

Six requests landed this release: the viewer got cheaper to leave open, more honest about what it just did, and easier to work in without leaving it; `flow`'s own traceability checks got harder to fool; and the GitHub issue bridge finally proved itself on the two issues it was built to close.

- The auto-refresh stops paying for a cache that can never hit
- A status change and its commit become one step, not two
- Documents edit in place in the browser
- The viewer link travels with the document
- `flow`'s traceability checks get harder to fool, and its own writes stop tripping its own lint
- The GitHub issue bridge, proven on the case that motivated it

[Full release note](https://github.com/AlexAgo83/logics-manager/releases/tag/v2.22.0)

## 2.21.7

Seven requests, filed after a review of the open corpus, and one theme running through four of them: the corpus can be wrong about itself, quietly. Lineage inferred from prose, proof matched by a number two unrelated documents happen to share, a report so full of expected findings that a real one would be skimmed past, and pointers into code that moved. Plus a viewer menu that had drifted from its own registry, and a naming papercut paid by every path guess.

- Lineage is what a document declares, not what it mentions
- A non-empty audit report now means an operator is needed
- Docs are told when their code anchors stop resolving
- Acceptance proof can be recorded when it is produced
- The Workshop menu is generated from its registry
- Either spelling of a workflow directory now resolves
- A generated `# AI Context` asks to be filled
- Also

[Full release note](https://github.com/AlexAgo83/logics-manager/releases/tag/v2.21.7)

## 2.19.6

Agent-facing correctness. A full field session on an external project produced sixteen findings, all of the same shape: an agent that trusted the tool's output produced wrong work. Generated documents asserted things that were false about the project they described, and commands reported outcomes that had not occurred. This release closes all of them, each covered by a regression test using the field report's verbatim strings.

- Commands report what they actually did
- Scaffolded tasks no longer assert work that has not happened
- Closeout accepts precise validation evidence
- Indicator updates are kind-aware and honestly exitable
- Reference handling
- Companion documents and discoverability
