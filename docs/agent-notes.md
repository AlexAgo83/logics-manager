# Agent notes

Pitfalls and operator rules for any agent working in this repo (tracked here because AGENTS.md is local and ignored).

## Agent pitfalls (moved here from agent memory, 2026-10-28)
- `logics-manager` on PATH is the published npm package (`/usr/local/lib/node_modules/@grifhinz/logics-manager`), not this checkout. To exercise local changes: `node scripts/run-python.mjs -m logics_manager <cmd>` (for example `... view --port 8788 --no-open`). Otherwise a dev viewer serves the old bundle and `audit` still reports a fixed blocker.
- Test cadence: never run the full suites (`npx vitest run` without a target, `pytest tests/python`) unless the operator asks; they take minutes while the operator waits. Run the targeted files (`grep` for the tests of a shared behaviour). For a display bug, measure it in the viewer: that is the proof. To reproduce CI use `npm run test:coverage`, not bare vitest.
- Headless Chrome probes kill their child on every exit path (`exit`, `SIGINT`, `SIGTERM`, `uncaughtException` → `child.kill("SIGKILL")`), not only at the nominal end: eight leaked instances once kept the operator from opening their own Chrome. Check with `pgrep -fl "Google Chrome.*--headless"`.
- When citing a Logics doc to the operator, give the viewer link (`http://127.0.0.1:<port>/?focus=req_368`, `&read=1`, `&project=<name>`), with the port read once per session from `~/.cache/logics-manager/viewers.json`; no entry means no viewer is running, say so.
- Audit and AC traceability: a request AC clears `ac_missing_task_traceability` only when a linked task line holds both the AC id and `proof:`; `flow close backlog` writes the item line, the task line is added by hand or with `flow validate <req> --apply-fixes --proof`. Once any linked task is Done, every unproven AC turns blocking under `--governance-profile standard` (`any_task_done`): by design on an umbrella request; never fabricate proof, keep CI's audit step informational. `flow progress task` mirrors the same percentage onto every linked backlog item: write per-slice reality in the task's `# Report`.
- A process that "ignores" Ctrl+C: check `stty -f /dev/ttysNNN -a | grep isig` before suspecting handlers; a child that inherited the tty in raw mode and was killed never restores it (viewer runners use `stdin=subprocess.DEVNULL`).
- Viewer blank-page crash: read `~/.cache/logics-manager/viewer-diagnostics.jsonl` (or `logics-manager view diagnostics --format json`); a heap near the limit means OOM, a `blank-ui` entry a UI bug; breadcrumbs sit in localStorage `logics.localViewer.breadcrumbs`.
- Windows checks on Tower (`aagos@kdesktop`, clone `C:\Users\aagos\lm-wincheck`, Node 20 via choco): a `python3.exe` shim in `C:\Users\aagos\bin`, `npm run build:assets` then `npm run compile` before vitest, and `$env:PATH='C:\Program Files\nodejs;C:\Users\aagos\bin;C:\Python310;'+$env:PATH` in every SSH command.
- ChatGPT reaches the MCP surface through OpenAI Secure MCP Tunnel (ADR 031): profile `~/.config/tunnel-client/logics-manager.yaml`, key in `~/.config/logics-manager/tunnel.env` (600). `tunnel-client doctor` passes on an invalid key (it only checks the variable is set); a valid runtime key is ~164 characters starting `sk-proj`. The daemon must run when the connector is created.
