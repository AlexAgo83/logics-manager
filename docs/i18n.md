# Project i18n contract

Logics Manager supports an optional, project-owned i18n contract. It governs
JSON catalogs and viewer editing without prescribing a runtime library.

## Start source-only

Projects that own user-facing copy should consider i18n during bootstrap, even
when only one language ships initially:

```bash
logics-manager i18n init --source-locale en
logics-manager i18n validate
```

Initialization creates `logics/i18n/contract.json` and a source catalog. It
refuses to overwrite an existing contract or catalog. A repository without
user-facing copy can record that decision explicitly:

```bash
logics-manager i18n init --not-applicable --reason "No product UI"
```

Repositories without a contract remain valid; `i18n status` returns advisory
guidance rather than failing.

## Contract v1

An applicable contract declares:

- `schema_version`: `"1.0"`;
- `applicability`: `"applicable"`;
- `source_locale`, `default_locale`, and `fallback_locale`;
- a non-empty `locales` list containing those locales;
- `catalog.path`, with one `{locale}` placeholder and a repository-contained
  `.json` target.

Catalogs may be nested or flat JSON objects. Every leaf must be a non-empty
string. Keys must be stable, may not contain dots within a segment, and may not
contain braces or control characters. All locales must have exact key parity
and matching named placeholders such as `{name}`.

## Adopt existing catalogs

Create `logics/i18n/contract.json` with the existing catalog path pattern, then
run:

```bash
logics-manager i18n status
logics-manager i18n plan
logics-manager i18n validate
```

`plan` reports deterministic next actions. It does not translate or rewrite
runtime code. When an existing runtime uses visible source text as identifiers,
migrate to semantic keys in bounded domains. A compatibility namespace may be
kept temporarily when its remaining entries are counted and its removal is
gated by regression coverage.

## Add a locale

Add the locale to the contract, copy the source catalog to the declared target,
translate values without changing keys or placeholders, then validate. The
viewer reads the declared catalogs after validation and can edit existing
string values inside the selected repository.

## CI and recovery

Use this non-mutating gate in CI:

```bash
logics-manager i18n validate
```

Invalid declared contracts fail closed with diagnostics for schema errors,
path escapes, missing catalogs, invalid keys or leaves, locale parity, and
placeholder parity. Fix the reported contract or catalog; heuristic viewer
detection is intentionally not used to bypass an invalid declaration.

## Rollout evidence

The v1 rollout was exercised across anonymized project shapes: existing
multi-locale JSON catalogs, a phrase-key migration, a staged DOM-translation
migration, and five source-only React/Next/Vite applications. Each project kept
its own runtime adapter and validation suite, demonstrating that the contract
is framework-neutral.
