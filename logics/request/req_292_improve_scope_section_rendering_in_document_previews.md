# Needs
- Document previews should render `# Scope` sections with clear `In` and `Out` groups instead of a visually flat nested bullet list.
- The fix should improve readability for generated backlog docs without changing the Logics markdown source format.
- The implementation should stay inside the existing shared markdown renderer and viewer CSS, with no new dependency or document schema change.

# Context
- The current preview already recognizes section heading kinds: `Scope` receives `markdown-preview__section-heading--scope` and an orange accent.
- Backlog docs generated by the scaffold commonly use `# Scope` followed by bullets shaped as `- In:`, indented child bullets, `- Out:`, and indented child bullets.
- The current markdown parser normalizes any `- ...` line into one flat list item, so indented child bullets lose hierarchy and `In:`/`Out:` read like ordinary bullets.
- The screenshot from the desktop shows this exact failure: the Scope heading is visible, but the group labels and scope bullets are hard to scan.
- A minimal implementation can detect the common Scope list shape after a Scope heading and render it as two scope groups with existing inline markdown support.

# Acceptance criteria
- AC1: A `# Scope` section containing `- In:` / `- Out:` group labels and indented child bullets renders as two visually distinct scope groups.
- AC2: `In` and `Out` labels are rendered as group headers, not as ordinary bullet items, and child bullets remain readable with proper spacing and indentation.
- AC3: Inline markdown inside scope child bullets, including code spans and workflow refs, continues to render through the existing inline renderer.
- AC4: Non-Scope lists and unsupported Scope list shapes continue to render exactly as generic lists.
- AC5: The renderer remains dependency-free and does not change Logics markdown source, schema, scaffold output, or backend payloads.
- AC6: Tests cover the Scope-specific rendering, generic list fallback, and a viewer document preview containing a Scope section.
- AC7: `npm run bundle:viewer-host`, `npm run check:viewer-host`, targeted vitest checks, `npm run lint:ts`, and `logics-manager lint --require-status` pass.
