## Validation environment

Run every local check through `.jarvis-input/mission-test-runner.py`; exact
commands, durations, and exit codes are in
`.jarvis-artifacts/mission-tests.jsonl`. Completed-run durations include shared
lock waiting, recorded separately in `lock_wait_s` when acquisition succeeds.

Initial attempts unset inherited `GIT_DIR`, `GIT_WORK_TREE`, and
`GIT_COMMON_DIR` before launching the timer so temporary Git repositories in
tests are independent of the mission checkout. However, this isolated checkout
requires its supplied Git routing: its on-disk gitdir points outside the sandbox.
A local `.jarvis-artifacts/bin/git` adapter restores the supplied routing only
for commands targeting this checkout (including `-C` handling), leaving temporary
fixture repositories independent. It supplies the public origin from `package.json`
as a process-only Git option because the isolated Git snapshot has no remote.
Public pytest, coverage, and ruff were installed into the existing local virtual
environment without changing dependency manifests. `.venv/bin` was added to
PATH for the complete Python checks.

The initial `npm test` run failed in `tests/npmPackage.test.ts` because the
Mermaid bundle had not been generated, and in `tests/viewer.campaign-report.test.ts`
because Chromium was not discoverable on PATH. Compilation generates the bundle;
a local, untracked `.jarvis-artifacts/bin/chromium` symlink exposes the prepared
shared Playwright browser without changing repository tooling. A retry after
compilation resolved the package test; the browser prerequisite required the
additional PATH correction.
